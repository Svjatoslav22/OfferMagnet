# OfferMagnet — Контекст Проєкту (PROJECT_CONTEXT.md)

## 1. Огляд проєкту
- **Головна ідея:** Автономний персональний AI-агент для автоматизованого пошуку вакансій, інтелектуальної оцінки їх відповідності резюме (CV matching), генерації адаптованих супровідних листів та автоматичної відправки відгуків (auto-apply).
- **Цільова аудиторія:** IT-спеціалісти (розробники, інженери), які шукають роботу в Україні або дистанційно (remote) на міжнародному та локальному ринках.
- **Призначення:** Звільнити кандидата від щоденного моніторингу job-бордів, автоматично фільтрувати нерелевантний спам за допомогою LLM (Gemini через OpenRouter), готувати релевантні супровідні листи та забезпечувати зручне керування відгуками через Telegram-бота або веб-дашборд.

---

## 2. Технічний стек
- **Мова:** TypeScript (Node.js, ES Modules, запуск через `tsx`).
- **Веб-фреймворк:** Next.js 16 (App Router, Server Actions, React 19).
- **UI & Стилі:** Tailwind CSS v4 (`@tailwindcss/postcss`), Lucide React, `clsx`, `tailwind-merge`.
- **База даних & ORM:** PostgreSQL, Prisma ORM 7 (`@prisma/client`, `@prisma/adapter-pg`, драйвер `pg`).
- **Штучний інтелект (AI / LLM):** OpenRouter API (клієнт `openai`, модель за замовчуванням `google/gemini-2.5-flash`).
- **Скрапінг та автоматизація:** Cheerio (швидкий HTML-парсинг), Playwright (`playwright-core` для емуляції браузера та авто-відгуків).
- **Telegram-бот:** Grammy (`grammy` фреймворк для Node.js).
- **Планувальник та черги:** `node-cron` для періодичного запуску за розкладом; асинхронна черга завдань через таблицю `Job` в БД.
- **Деплой & Інфраструктура:** Docker, docker-compose, підтримка Vercel (дашборд) + Railway/VPS (воркер, бот, cron).

## 3. Архітектура та структура папок
- `src/` — вихідний код застосунку:
  - `ai/` — логіка взаємодії з LLM:
    - `ai.client.ts` — клієнт OpenRouter на базі `openai` SDK.
    - `matcher.service.ts` — скоринг вакансій під CV кандидата, аналіз співпадіння/відсутності навичок.
    - `cover-letter.service.ts` — генерація персоналізованого супровідного листа під конкретну вакансію.
  - `app/` — веб-інтерфейс Next.js:
    - `page.tsx`, `layout.tsx`, `globals.css` — головна сторінка дашборду та стилі.
    - `actions.ts` — Server Actions для зміни статусів вакансій, ручного тригеру скрапінгу та оновлення профілю пошуку.
  - `bot/` — Telegram-інтерфейс:
    - `bot.ts` — ініціалізація бота, команди (`/start`, `/scan`, `/stats`), обробка inline-кнопок.
    - `notifier.service.ts` — формування та надсилання карток вакансій і сповіщень кандидату в Telegram.
  - `components/` — React-компоненти:
    - `dashboard-app.tsx` — інтерактивна Kanban-дошка вакансій (фільтри, картки, деталі матчу, відгуки).
    - `stats-overview.tsx` — аналітичні картки зі статистикою по статусах та конверсіях.
  - `lib/` — допоміжні утиліти:
    - `utils.ts` — хелпери для класів Tailwind та форматування.
  - `scheduler/` — планування та оркестрація:
    - `cron.ts` — конфігурація періодичного CRON-розкладу.
    - `orchestrator.ts` — координатор пайплайну: скрапінг -> дедуплікація -> попередні фільтри -> AI-скоринг -> збереження в БД -> сповіщення.
  - `scrapers/` — модулі збору вакансій:
    - `work-ua.scraper.ts`, `robota-ua.scraper.ts`, `dou.scraper.ts`, `djinni.scraper.ts`, `jobico.scraper.ts` — скрапери для відповідних майданчиків.
    - `browser.ts` — спільна ініціалізація Chromium через Playwright.
    - `types.ts` — типи та інтерфейси зібраних вакансій (`RawVacancy`).
  - `scripts/` — сервісні скрипти:
    - `auth.ts` — збереження сесій та cookies для браузера.
    - `verify-work-auth.ts` — перевірка валідності cookies авторизації.
  - `services/` — бізнес-сервіси:
    - `apply.pipeline.ts` — оркестрація процесу подачі заявки з чергою та серіалізацією.
    - `playwright-apply.service.ts` — взаємодія з DOM job-сайтів для автоматичного надсилання відгуку та резюме.
    - `vacancy.service.ts` — збереження, оновлення та вибірка вакансій/матчів з БД.
    - `location-filter.ts`, `seniority-filter.ts`, `salary.ts` — алгоритми швидкої фільтрації.
  - `worker/` — фонові процеси:
    - `job-worker.ts` — воркер обробки черги завдань (`Job`), що зв'язує веб-інтерфейс з бекендом.
  - `db.ts` — ініціалізація клієнта Prisma з підключенням до PostgreSQL.
  - `index.ts` — ручний одноразовий запуск повного циклу скрапінгу та аналізу.
  - `run-bot.ts` — точка входу для продакшн-запуску бота, планувальника та воркера черги.
- `prisma/` — база даних:
  - `schema.prisma` — моделі даних: `User`, `SearchProfile`, `Vacancy`, `Match`, `Job`.
  - `clean.ts`, `seed.ts` — очищення та наповнення тестовими даними.
- `cookies/` — збережені сесії сайтів для Playwright (наприклад, `work.json`).
- `artifacts/` — директорія для артефактів (скріншоти виконаних авто-відгуків).

## 4. Поточний статус та стан розробки
- **Скрапінг:** Повністю підтримуються та працюють 5 джерел (Work.ua, Robota.ua, DOU, Djinni, Jobico).
- **Фільтрація та валідація:** Реалізовано багаторівневий відбір (дедуплікація за `source + externalId`, локація, рівень досвіду, зарплатні рамки).
- **AI Matching & Cover Letter:** Налаштована інтеграція з OpenRouter (Gemini), повертається точний JSON зі скорингом, matched/missing навичками та готовим супровідним листом.
- **Telegram Bot:** Працює в режимі Long Polling, надсилає сповіщення про гарячі вакансії (score >= поріг) з кнопками "Відгукнутися", "Відхилити", "Відкрити сайт".
- **Auto-Apply:** Працює пайплайн подачі відгуку через Playwright для Work.ua з використанням збережених cookies авторизації та прикріпленням CV у форматі PDF.
- **Веб-дашборд:** Інтерактивна Kanban-дошка з відображенням деталей матчу, перемиканням статусів, моніторингом фонових завдань та редагуванням профілю користувача.
- **Архітектура черг:** Розділено веб-рівень та бекенд-воркер через БД-чергу `Job`, що дозволяє хостити фронтенд на serverless-платформах (Vercel).

## 5. Правила коду та домовленості
- **Фокус задач:** Працювати тільки зі вказаними файлами без зміни непов'язаних модулів чи архітектурного рефакторингу без запиту.
- **Стиль коду:** Строгий TypeScript, заборона використання `any` без критичної необхідності, дотримання ES Modules.
- **Безпека:** Усі API-токени, рядки підключення до БД та секрети зберігаються виключно в `.env` (використовувати `.env.example` як шаблон).
- **Сторонні залежності:** Не додавати нові бібліотеки без попереднього погодження з користувачем.
- **Серіалізація авто-відгуків:** Playwright-дії на подачу заявок виконуються суворо послідовно через чергу/серіалізатор, щоб уникнути конфліктів сесій та блокувань.
- **Валідація білду:** Після внесення будь-яких змін у кодову базу обов'язково перевіряти працездатність команди `npm run build`.
